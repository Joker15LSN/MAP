> 版本：2.1（deep module + 文档基线对齐版）
> 审查基线：2026-08-24，分支 `qoder/dev-modelscope`，提交 `e781ecd8`。
> 本文供后续 agent 执行；不授权跳过兼容性、数据迁移、安全、流量排空或验收门禁。

## 1. 结论

当前仓库确有过度设计，但“文件大”不是主要判据。真正的问题是迁移态留下了多套执行真相、过宽 interface、假 seam 和跨 caller 泄漏的协议知识：

1. 现有 conversation message proxy 仍是过渡路径，ADR-0002 已规定最终执行模型是 `Conversation -> Run -> Step/Attempt -> Invocation/Approval/Artifact -> Event/Checkpoint`，新 HTTP 路径为 `/api/v1/runs*`。先深度重构 conversation stream，再实现 Run，会造成“先重构、后删除”。
2. 同一个 Sandbox Effect 同时经过 BFF `JobRunner/EffectGuard` 与 core `SandboxInvocationLedger/Reconciler`，lease、fence、unknown outcome、identity 和错误映射跨 seam 重复。
3. `JobHandler(Job, AsyncSession)` 的类型很小，真实 interface 却要求 caller 理解 context variable、lease safe point、禁止自行 commit、lease loss 返回值、异常分类和 EffectGuard 顺序。
4. `ConfigRepository` 仅声明 `load/update`，但 `ConfigMutationService` 直接要求 concrete `AdminStateStore.prepare_update/apply_prepared`；当前 seam 与 implementation 不一致。
5. `LLMEngine` 虽有 1,872 行，但 deletion test 表明它已经集中重试、响应归一、structured fallback、usage 与 tracing。正确方向是收窄同义 interface 并深化 ModelInvocation，而不是拆成多个互相转发的浅 module。
6. `AgentRuntime` 已集中 memory、hooks、result normalization 与并发取消，具备 depth；双引擎排空后应删除 `RuntimeAgent` hypothetical seam、engine switch 和 compat session，而不是把执行知识重新散回 dispatcher。

因此，本轮总原则是：

> 先建立唯一 deep module 和真实 seam，再物理删除过渡实现；不以拆文件数量、类数量或 LOC 下降代替 architecture 改善。

## 3. Deepening 候选与顺序

| 顺序 | 候选 | 强度 | 依赖类别 | 结论 |
| ---: | --- | --- | --- | --- |
| 1 | Canonical Run module | Strong，Top recommendation | ports & adapters + local-substitutable | 先成为唯一执行真相，避免深化即将删除的 message proxy |
| 2 | Run Attempt module | Strong | local-substitutable + mock | 隐藏 lease/transaction/fencing，缩小 handler interface |
| 3 | Sandbox Invocation module | Strong | ports & adapters + local-substitutable | 明确唯一 durable owner，消除双 ledger 语义与 raw HTTP 泄漏 |
| 4 | Runtime Snapshot module | Strong | local-substitutable | 取代 generic AdminState updater 和 concrete store 泄漏 |
| 5 | ModelInvocation module | Strong | true external / mock | 保留 `LLMEngine` depth，删除同义 interface 与 caller 旁路 |
| 6 | Agent Execution module | Strong after canary | in-process | 单引擎后删除 hypothetical seam，保留 runtime depth |
| 7 | typed Event emission | Strong，依赖 Run/OTel | ports & adapters | 取代 `state_store/state_id/record_event(dict)` plumbing |

管理台 `AdminApi` 和 observability 超大文件确有 shallow interface 候选，但不属于最近最强热点；先放入 backlog。除非出现真实变更压力，不因 LOC 单独提升优先级。

### 3.1 Architecture decision gate

任何候选进入实现前，owner 必须先选定候选并完成 grilling。若需要决定 module 的具体 interface，执行 design-it-twice：至少给出两种明显不同的 interface 方案，比较 depth、seam、leverage、locality 和测试面。

本计划只冻结方向和验收条件，不预先规定具体方法名。

## 4. 所有 agent 必须遵守的规则

执行前先读根 `AGENTS.md` 和 `docs/README.md`，再进入任务对应的 contract、ADR、SDD/TDD 与测试文档。

1. 使用 `module`、`interface`、`implementation`、`depth`、`seam`、`adapter`、`leverage`、`locality` 描述 architecture，不用模糊的“多拆几层”作为方案。
2. 对每个待删 module 执行 deletion test：删除后复杂度若消失或仅集中到一处，它可能 shallow；若复杂度散回多个 caller，它正在提供 depth，不应直接删除。
3. Interface 是测试面。新测试通过 module interface 观察结果；只有明确的 internal seam 可以保留 adapter/CAS 级测试。禁止为了测试方便把 implementation 细节升级为 public interface。
4. 一个 adapter 只是假设 seam；两个 adapter 才证明 seam 真实。常见合理组合是 production HTTP/PostgreSQL adapter + deterministic in-memory adapter 或 mock adapter。
5. 新 abstraction 必须满足至少一项：两个真实 adapter；隔离 true external dependency；表达 ADR/规范中的稳定领域概念。禁止为单一 caller 新增 `Manager/Factory/Registry` 转发链。
6. 先记录 consumer、流量、数据、契约和测试证据再删除。`rg` 零引用不能证明 route、反射、配置或外部流量为零。
7. 结构改造不得顺手改变错误码、SSE 顺序、Event schema、事务、fencing、安全策略或 stop/done 竞态语义。
8. 每个 PR 只处理一个 deepening candidate 或一个高度内聚的迁移子步骤；删除与流量排空不得塞进同一个不可回滚提交。
9. 测试 replacement，而非 layering：新 interface 测试稳定后，删除穿透旧 shallow module 的测试；不要永久保留两套测试面。
10. 每一步完成后更新本文状态、实际命令、结果与回滚点；失败时停止，禁止放宽测试制造绿灯。

## 5. 不应误删的必要复杂度

- ADR-0002 的单写者、状态机、Event sequence、idempotency、64KiB/ArtifactRef、typed error 和 workspace isolation。
- `JobRunner` 的 lease、attempt fencing、Effect unknown outcome、crash recovery；目标是内化它们，不是弱化它们。
- OpenSandbox 的无宿主 fallback、idempotency、lost response reconcile、terminal-before-destroy 与 fail-closed。
- Runtime Snapshot 的 CAS、不可变版本、审计 hash chain、recovery 和 rollback。
- Alembic 历史、根 `e2e/`、`SseStreamParser`、`packages/map-tree-core`。
- 三份 byte-identical CORS policy 当前是独立 uv/Docker context 下的有意 vendoring，并有 parity test；没有先调整 package/build context 前不合并。
- 安全校验、输入规范化、超时、重试和观测不能仅因 C901 较高而删分支；先建立 characterization test。

### Step 2：深化 Canonical Run 与 Run Attempt

优先级：P0；风险：高；依赖：Step 0、P0-CONTRACT-01；对应 P1-RUN-01。

先完成候选 grilling；不得先把 `stream_conversation_message` 机械拆成多个 exported helper。

工作：

1. 以 ADR-0002 固定的 Conversation、Run、Step/Attempt、Invocation、Effect、Event/Checkpoint 为唯一领域模型。
2. 让 Canonical Run module 内化创建、单写者执行、Event append/replay、checkpoint、cancel/retry/reconcile 与 SSE projection。
3. PG 是 local-substitutable internal seam；真实 PostgreSQL adapter 与测试 adapter 均须通过同一 contract。不得用 SQLite 模拟 `SKIP LOCKED`、数据库时钟或 CAS。
4. BFF→core 是 remote-owned seam：production transport adapter 和 deterministic in-memory adapter 必须共享 typed Event/result contract。
5. 将 `JobRunner` 深化为 Run Attempt implementation：handler 不再通过 context variable 获取隐式规则，不再自行决定 commit、lease loss 或异常到终态的映射。
6. Effect provider 保留为 internal seam；低层 `record_intent/begin/adopt/ack/mark/snapshot` 不再成为一般 caller 的 interface。
7. `EventEnvelope` 与状态机保留为规范核心；`run_event_stream.py` 的 test-only row helper 要么被 Run persistence adapter 吸收，要么在 consumer=0 后删除。
8. 用 Canonical Run interface 测试一次 Conversation turn 的 durable facts、Event 顺序、重连、stop/done/timeout/retry/reconcile 五方竞态和 crash takeover。

完成条件：

- state machine 有 production writer；`(run_id, seq)` 唯一且可 replay。
- handler 的真实 interface 不再包含未声明的 transaction/fencing 规则。
- 旧逐方法 EffectGuard 测试被稳定 interface 测试替代；必要 CAS 测试明确标记 internal seam。
