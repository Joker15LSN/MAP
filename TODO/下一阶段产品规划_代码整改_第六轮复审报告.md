## 5. 剩余问题

## R6-P2-01：product -> docs rename 可绕过 clean-product final gate

### 证据位置

- `scripts/source_control.py:59-87`：parser 正确保存 rename 的 `path` 和 `orig_path`；
- `scripts/source_control.py:137-139`：`dirty_files` 只收集 `entry["path"]`，`dirty_product` 也只分类新路径；
- `map-business-backend/tests/test_source_control_snapshot.py:125-136`：现有 rename 测试反而断言 `old_name.py` 不在 `dirty_files`，没有测试跨 docs/product 边界；
- gate 与 E2E 都复用该 snapshot，因此两者同时受影响。

### 真实重放

在临时真实 Git 仓库中：

```text
baseline: app.py（已跟踪产品文件）
git mv app.py TODO/app.py.md
```

snapshot 输出：

```json
{
  "entries": [
    {
      "xy": "R ",
      "path": "TODO/app.py.md",
      "orig_path": "app.py"
    }
  ],
  "dirty_files": ["TODO/app.py.md"],
  "dirty_product": [],
  "docs_only_dirty": true
}
```

`source_control.main(... --require-clean-product)` 返回 0；正确结果应为 2。

### 根因

rename 是“旧路径删除 + 新路径增加”。新路径位于 TODO 并不改变旧 `app.py` 是产品文件的事实。当前 parser 虽保存双路径，分类层却把 `orig_path` 丢弃，导致跨分类 rename 被当成纯文档修改。

### 风险

- final gate 可在产品文件被删除或移出产品目录时继续运行并标记 clean product；
- E2E artifact 会记录 `docs_only_dirty=true`，与真实受影响文件集合不一致；
- 当前第六轮 artifact 是真正 clean tree，不受该绕过污染；风险面是未来 dirty final run 和证据防线完整性，而非本轮已验证的业务行为。

### 整改方向

1. 为 rename 构造完整 affected-path 集合：新路径 `path` 和旧路径 `orig_path` 都必须参与 docs/product 分类；
2. 建议显式输出 `affected_paths`，并让 `dirty_files`/`dirty_product` 使用相同去重后的集合；若为兼容保留 `dirty_files` 只含目标路径，也必须让 `dirty_product` 独立检查 rename 原路径；
3. rename 从 product 到 docs 时必须 product dirty；从 docs 到 product 时也必须 product dirty；product 到 product 必须 product dirty；只有 docs 到 docs 才可 docs-only；
4. copy 与 rename 要区分：copy 的 origin 未被删除，可按目标路径分类，但 artifact 仍应保留 origin 供审计；
5. gate/E2E 继续只调用共享模块，禁止再加入第二套路径修补逻辑。

### 整改验收标准

- 固化本轮 `app.py -> TODO/app.py.md` 失败复现，`--require-clean-product` 必须 exit 2；
- 新增 product->product、product->docs、docs->product、docs->docs 四象限 rename 测试；前三者 `dirty_product` 非空，最后一项 `docs_only_dirty=true`；
- 中文、空格、staged+unstaged、删除、untracked 和首行路径现有 11 项继续通过；
- gate 和 E2E 对同一 rename 仓库输出完全一致的 affected path 与分类；
- 修复提交后执行 `RELEASE_GATE_FINAL=1`，确认 clean HEAD 22/22；
- 至少执行一次 `MAP_E2E_FINAL=1 --suite pr`，证明 E2E 使用修复后的 snapshot；
- 若修复仅涉及 `scripts/source_control.py` 及其测试，可保留本轮两次 full E2E 作为业务回归证据；若改动 effect、worker、browser 或运行时产品代码，则必须重新执行两次 full E2E。
