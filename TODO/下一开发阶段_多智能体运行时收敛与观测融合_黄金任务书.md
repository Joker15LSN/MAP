- 任务的数据迁移、负向/故障/安全测试、旧路径删除、文档同步和验收证据都属于交付范围。

## 2. 不可破坏的目标边界

1. 浏览器只调用版本化 `conversation/run` API，删除 `/api/chat*`。
2. `Conversation -> Run -> Step/Attempt -> Invocation/Approval/Artifact -> Event/Checkpoint` 是唯一执行模型；PG 是 durable truth。
3. AgentScope 2.0.6 是唯一 Agent loop；legacy `ToolCallAgent` 通过量化灰度后删除。
4. 生产代码/命令/文件执行唯一调用 OpenSandbox Server；map_core 不挂 Docker socket/kubeconfig，不存在宿主/本地 fallback。
5. 生产记忆/检索/上下文索引唯一调用 OpenViking Server；Mongo memory 只是迁移源，不是目标 provider。
6. PG 保存对话/Run/事件，Object Store 保存原始 Artifact，OpenViking 保存可检索记忆和引用；三者不互相冒充。
7. 配置唯一事实源是 PG immutable snapshot；一个 Run 只绑定一个 `config_snapshot_id`。
8. OTel/OTLP 是唯一 telemetry 发射入口；`map-observability` 查询 OTel-native backend/派生投影，应用不再双写 Mongo telemetry。
9. Tool/MCP/Skill/Sandbox/Artifact 共用 capability manifest、policy、approval、credential scope 和 durable audit，缺配置一律 fail-closed。
10. BFF 事务创建 Run/command；持有 lease 的 Run worker 是执行期唯一写者；map_core 只返回 typed events/results。

OpenSandbox 和 OpenViking 均以独立 Server 形式部署，算法链路仅通过带 service identity、workspace namespace、timeout/熔断和 trace context 的异步 HTTP 请求调用。版本决策依据：[AgentScope v2.0.5 开始支持 OpenSandbox Workspace](https://github.com/agentscope-ai/agentscope/releases/tag/v2.0.5)、[OpenSandbox](https://github.com/opensandbox-group/OpenSandbox)、[OpenViking Server deployment](https://github.com/volcengine/OpenViking/blob/main/docs/en/guides/03-deployment.md)。

## 3. 通用交付与验收规则

- 每个 AC 生成一个 `tmp/acceptance/<TASK-ID>/<commit-sha>/<AC-ID>/evidence-manifest.json`，包含命令、退出码、assertion、artifact digest、commit 和 environment digest。
- `pass` 要求 exit code=0 且全部 assertion 通过；`blocked` 要求 reason/owner；`not-applicable-approved` 要求 waiver id/owner/expiry/reason。
- 所有 repository、claim、cache、outbox、SSE、artifact、memory、approval 和 telemetry projection 必须以 `workspace_id` 隔离；跨 workspace 资源统一 404。
- Run 终态只能是 `completed/failed/cancelled/timed_out`；Effect 的不确定使用 `uncertain/reconciling`，ModelInvocation 的不确定使用 `unknown/reconciled`。
- telemetry 故障不得改变业务终态；durable fact 写入失败必须 fail-closed 或保持可恢复 pending。
- OpenSandbox/OpenViking 的 contract、integration、fault 和 security 验收必须使用真实 Server，不得用 mock 代替。
- replay/fork 默认新建 Run/effect namespace，使用 mock/read-only provider；真实外部副作用必须显式审批。
- 发布候选必须执行 profile 中的 release gate、full E2E、security、fault、evaluation 和 migration/DR suites，unapproved skip/xfail=0。

**全局验收**

- `AC-EVIDENCE-01`：每个 P0/P1 AC 恰有一个最终 manifest，schema/digest/commit/environment/waiver 校验通过，发布时只允许 `pass` 或有效 `not-applicable-approved`。
- `AC-TENANT-01`：3 workspace × user/service/worker 生成式隔离矩阵全通过；启用 tenant 后扩展为 3 tenant × 3 workspace，零跨界读写。
